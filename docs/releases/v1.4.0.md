KSC now uses the KeanWISE schedule to confirm registrations. The desktop app adds Section Lookup and My Catches, shows the latest session checks, and keeps its data in one per-user folder shared by Portable and Setup.

## Registration and availability

- Dashboard still sends the first ordinary Add at the scheduled time. Auto-Catch and Cloud Phantom submit eligible sections as each opening is found, then reconcile the results at the end of the poll. Credit lookups run in the background, outside the first submission's path.
- Each target is verified against the same student's Degree Plans records for its own term. Confirmed registrations and waitlist entries are skipped on subsequent rounds. A new desktop task clears settled results and carries forward submissions that still need verification.
- Acknowledgements, duplicate messages, timeouts, and partial responses are checked against the account records. Uncertain results stay **Unknown**. An uncertain write needs two complete negative reads with a settling period before another attempt. After verification, the polling workers check availability again before retrying.
- Add and Waitlist use the section's fixed credits or the selected credits from the student's plan. When credits are unresolved, the request leaves the field out and the event log records that choice.
- Waitlist fallback requires a Closed rejection tied to the target and a schedule read confirming the target is unregistered. Drop-and-Add checks both sections first, avoids replaying a sent drop, and verifies that the dropped section left the schedule before reporting a successful swap.
- Unavailable seat data has its own status. A failed or unreadable poll is reported separately from a poll that finds no openings.

## Sign-in and session maintenance

- **Session Check** replaces the latency probe with a check for a signed-in KeanWISE page. It reports **Valid**, **Expired**, or **Unknown**. Recognized credential rejections trigger a single verified recovery attempt per task. Recovery requires the same account and a valid session.
- The session lifecycle study found that authenticated reads can return renewed cookies. KSC keeps those updates from verified responses. Cookie domain and path survive browser extraction and session import. An overlapping or outdated check cannot overwrite newer credentials.
- **Automatic Keepalive** runs while the desktop app is open after sign-in. Choose 5, 10, or 15 minutes, or turn it off. The default is 10 minutes. Recent authenticated traffic postpones maintenance, active registration pauses it, and server `Retry-After` is respected. A transient network failure gets one short recheck. When recovery needs a password or MFA, KSC prompts you to sign in again.
- **Session Check** and **Keep Alive Now** have separate controls and result histories. Dashboard and Auto-Catch show the same session summary with a countdown and the latest outcome of each action. The summary can be hidden in Settings. You can also sign in again as the same student during a scheduled countdown.
- **Use KSC browser profile** is an opt-in way to keep dedicated Edge and Chrome profiles for sign-in and recovery. KSC remembers the browser that last signed in with a dedicated profile. **Clear browser profile data** removes the KSC profiles, including retained legacy copies. Browser launch and credential extraction run in background threads.

## Section Lookup, history and logs

- **Section Lookup** reads course details, term, credits, seats, waitlist availability and account registration status for one or more IDs.
- **My Catches** saves the first verified registration that KSC submitted for each account, term, and section. See the request and response, timings, and the difference between course credits and credits sent. Filter by account or delete an individual local record. The view reuses loaded rows until the history changes.
- Structured JSON Lines logs keep per-section decisions, request timings and redacted diagnostic evidence. The app reports log or history write failures alongside the registration outcome.
- Dashboard and Auto-Catch have aligned controls and session status. Navigation leaves Section ID entry to an explicit click or tab. The frozen app uses its own icon and executable for Windows taskbar relaunch.

## Windows and local data

- **Portable** is a single executable. The x64 Inno Setup installer uses the same app binary and adds shortcuts and an uninstaller. Both show version 1.4.0 in Windows file properties.
- On Windows, settings, catch history, logs and dedicated browser profiles live under `%LOCALAPPDATA%\KeanSeatsCatcher`. Open the active directory from **Settings → Open Application Data Folder**. The folder persists when you replace Portable, switch builds, or uninstall through Setup.
- On upgrade, KSC imports an adjacent legacy `config.json` into an empty configuration, merges legacy catch history, preserves conflicting logs, and copies missing dedicated browser profiles. The original files stay on disk. If you used an older Portable build, close it and its browser, then run v1.4.0 once beside the old configuration.
- `KSC_DATA_DIR` selects an independent data store. `KSC_LOG_DIR` can direct logs elsewhere. The CLI archives a legacy `cloud_sniper.log` from its working directory.

## Cloud Phantom and Docker

- `--verify-only` reads per-section registration states and exits. The actual term comes from KeanWISE. Older commands with `--term` still parse.
- A worker using `--load-session` exits on confirmed expiry so you can export a fresh session. Webhooks follow confirmation of all targets.
- Compose persists logs and history in the host's `./logs` and mounts the session file read-only. Automatic restarts are off so a completed or stopped worker stays stopped. The build context is limited to CLI source and dependencies declared by the Dockerfile.

## Downloads

- `KeanSeatsCatcher_v1.4.0_Portable.exe` runs directly on Windows x64.
- `KeanSeatsCatcher_v1.4.0_Setup.exe` installs the app on Windows x64.

The builds target Windows 10 (1809 or later) and Windows 11. Both executables are unsigned.
